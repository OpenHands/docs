title: DigitalOcean Managed Agents
description: Run Agent Canvas conversations in isolated DigitalOcean sandboxes using Managed Agents as a backend.
---

You can connect Agent Canvas to [DigitalOcean Managed Agents](https://www.digitalocean.com/products/managed-agents) as a backend. The desktop app and browser UI use the same **Providers** flow. Each conversation runs in a DigitalOcean sandbox: a dedicated microVM with its own disk, terminal, and browser tools.

<Note>
  DigitalOcean Managed Agents is in public preview, and DigitalOcean bills sandbox usage to your DigitalOcean account. Your LLM provider bills model usage separately.
</Note>

## When to Use It

A DigitalOcean backend is a good fit when you want to:

- Run agents in isolated cloud sandboxes without managing a VM, Docker host, or Kubernetes cluster
- Pay only while a sandbox is working: idle sessions pause automatically and stop compute charges
- Keep separate, disposable environments for separate tasks
- Use the same managed backend workflow in the desktop app or browser UI

## Prerequisites

- Agent Canvas version 1.28.0 or later, running as the [desktop app or in your browser](/openhands/usage/agent-canvas/setup).
- A [DigitalOcean account](https://cloud.digitalocean.com/registrations/new) with a payment method and funds in at least one balance.
- A DigitalOcean personal access token for the team you want to use. See [Create a Token](#1-create-a-token).
- An API key for your LLM provider. You add it after connecting.

## 1. Create a Token

1. Sign in to the [DigitalOcean control panel](https://cloud.digitalocean.com) and switch to the team you want Agent Canvas to use.
2. Open **API** → [**Tokens**](https://cloud.digitalocean.com/account/api/tokens) and select **Generate New Token**.
3. Give the token a name and an expiration, and grant it **Full Access**.
4. Copy the token. DigitalOcean only shows it once.

A token belongs to one DigitalOcean team. To connect a different team, create a token in that team and add it as another connection.

## 2. Connect Agent Canvas

1. Open the backend switcher in the top bar and choose **Manage Backends** → **Add Backend**.
2. Under **Choose how you want to connect**, select the **Providers** tab, then **DigitalOcean**.

    ![Agent Canvas Choose how you want to connect dialog with the Providers tab selected, showing the DigitalOcean provider and the note that more providers are coming soon.](/openhands/static/img/agent-canvas-add-backend-providers.png)

3. Paste the token into **Personal access token** and select **Connect with token**.

If you have not created a token yet, the **Create a token** link next to the field opens the DigitalOcean tokens page.

The desktop app encrypts the token with your operating system's keychain, so you stay signed in after restarting the app. If no keychain is available, Agent Canvas warns that the connection lasts only until you quit.

## 3. Create an Agent

A DigitalOcean **agent** is a saved setup for OpenHands sessions. Each **session** you launch from it is a separate sandbox with its own disk and conversations.

After you sign in, the DigitalOcean panel lists your team's **OpenHands agents**. Each row shows the agent's latest session status, and the footer shows the connection you signed in with and a **Sign out** button.

![Agent Canvas DigitalOcean panel listing three OpenHands agents: one with no sessions yet, one waiting for the agent server, and one with a paused session. New Agent and refresh buttons sit above the list, and the footer shows the DigitalOcean token connection with Sign out.](/openhands/static/img/agent-canvas-digitalocean-agents.png)

1. In the **OpenHands agents** list, select **New Agent**.
2. Enter an **Agent name**: up to 64 letters, numbers, `-`, `.`, or `_`, starting and ending with a letter or number.
3. Choose a **Sandbox size**, or keep **Default (DigitalOcean picks)**. Each option shows its vCPUs, memory, and monthly price.
4. Select **Create and launch**.

<Note>
  Sandbox size applies to every session of an agent and cannot be changed later. To use a different size, create another agent.
</Note>

Agent Canvas lists only agents that run OpenHands. Agents you created in the DigitalOcean control panel for other harnesses, such as Claude Code or Codex, do not appear here.

## 4. Wait for the Session to Start

Agent Canvas launches the agent's first session and connects to it. The status moves through **Waking the session…**, **Connecting to the session…**, and **Waiting for the agent server…**. A new sandbox can take a few minutes to start; resuming a paused session is faster.

When the session is ready, Agent Canvas adds it as a backend named after the session, selects it, and opens a new conversation.

## 5. Set Up Your Model

Each session has its own agent-server, so it starts without an LLM configured.

1. Open **Settings → LLM**.
2. Add an [LLM profile](/openhands/usage/agent-canvas/llm-profiles) with your provider, model, and API key.
3. Start a conversation.

To keep model usage on DigitalOcean too, choose the `digitalocean` provider in the LLM profile and enter a DigitalOcean model access key. See [DigitalOcean Inference](/openhands/usage/llms/digitalocean).

Your LLM key is stored inside the session's sandbox, not in the DigitalOcean agent. Every new session needs its own LLM setup.

## Work With Agents and Sessions

While a DigitalOcean backend is selected, the sidebar shows the agent's sessions instead of the usual conversation list. The current session expands to show its conversations.

- Select **+** in the sidebar header to launch a **New session** for the same agent.
- Open the agent menu to **Switch agent** or **Manage agents**.
- **Manage agents** opens the full DigitalOcean view, where you can search, filter, and act on every agent and session.

To open an agent from **Add Backend** later, select it in the **Providers** list. Agent Canvas resumes its most recent session, or launches one if it has none. Expand the agent to choose a specific session.

### Session Status

| Status | Meaning |
|--------|---------|
| **Running** | The sandbox is up and ready for conversations. |
| **Starting** | The sandbox is booting. |
| **Paused** | Compute is stopped. Files, installed tools, and conversations are kept. |
| **Failed** | The sandbox did not start. Launch a new session. |
| **Ended** | The session was stopped and its sandbox deleted. |

### Session and Agent Actions

| Action | What it does | Can you undo it? |
|--------|--------------|------------------|
| **Connect** / **Open** | Opens the session as your active backend. | — |
| **Resume & connect** | Wakes a paused session, then connects. | — |
| **Pause session** | Stops compute charges and keeps the session's files and conversations. | Yes, resume it |
| **Stop session** | Ends the session and deletes its sandbox, files, and conversations. | No |
| **Delete agent** | Deletes the agent so no new sessions can launch from it. Available only after all of its sessions are stopped. Paused sessions must be stopped too. | No |

### Disconnecting vs. Stopping

When you remove a DigitalOcean backend in **Manage Backends**, Agent Canvas asks what to do:

- **Disconnect only** removes the backend from Agent Canvas. The session keeps running, and billing, until it pauses on its own. You can reconnect from **Manage agents**.
- **Stop session** ends the session and deletes its sandbox, then removes the backend.

<Warning>
  Stopping a session permanently deletes its sandbox, including any files the agent created. Push work you want to keep, for example to a Git remote, before you stop a session.
</Warning>

### Reconnecting After a Restart

Agent Canvas keeps the backend entry when it stops, but the connection to the sandbox closes. When Agent Canvas starts again, it reconnects to the selected DigitalOcean backend automatically after DigitalOcean sign-in is available. A DigitalOcean backend can show as disconnected in **Manage Backends** while it is not selected. Select it to reconnect.

<Note>
  The desktop app can store your token in your operating system's keychain. The browser UI keeps a token entered in the UI only until its server or container stops. See [Browser Sign-In](#browser-sign-in).
</Note>

## Costs

DigitalOcean bills each session for the CPU it actually uses, its peak memory, and its storage. See [Harness Runtime pricing](https://docs.digitalocean.com/products/managed-agents/agent-harness-runtime/details/pricing/) for current rates and sandbox sizes.

To keep costs down:

- **Let idle sessions pause.** DigitalOcean pauses a session after 15 minutes without activity. A paused session stops compute charges but still pays for storage.
- **Switch away when you are done.** Agent Canvas checks only the selected backend, so a session you are not using can go idle and pause.
- **Stop sessions you no longer need.** Stopping deletes the sandbox and its storage charges.
- **Pick the smallest size that works.** The default size suits most coding tasks.

Sessions pause when all of your DigitalOcean balances reach $0, and stay paused until you add funds. Each team can have a limited number of sessions at once; paused sessions count toward that limit until you stop them.

## Security

- In the desktop app, your DigitalOcean token stays in the desktop process and is never sent to the web page.
- In the browser UI, your DigitalOcean token stays in the Agent Canvas server and is never sent to the browser.
- Revoke the token in DigitalOcean to disconnect Agent Canvas. If you supply `MARS_TOKEN` at startup, keep the env file readable only by you (`chmod 600`) and out of version control.
- Each session runs in its own microVM, separate from your machine and from other sessions.
- Secrets and API keys you add in a session's settings are stored in that sandbox. The agent can read them while it works, as with any backend.
- Sessions can reach the public internet. They cannot reach private DigitalOcean VPC resources.
- Everyone on a DigitalOcean team can see that team's OpenHands agents and sessions.

## Browser Sign-In

The browser UI shows **Providers** by default. You do not need to set `MARS_WEB=1` or use a different connection flow. Start Agent Canvas, then follow [Connect Agent Canvas](#2-connect-agent-canvas).

The browser UI uses a DigitalOcean personal access token and does not offer OAuth sign-in. A token entered in the UI stays in server memory, not in the settings volume. After the Agent Canvas server or Docker container restarts, enter the token again.

### Optional: Sign In Automatically After Restarts

If you manage the Agent Canvas server, you can supply `MARS_TOKEN` when it starts. This keeps the server signed in across restarts without changing the UI flow.

<Warning>
  Anyone who can read this environment variable can use your DigitalOcean account. Keep env files readable only by you (`chmod 600`) and out of version control. Revoke the token in DigitalOcean if it is exposed.
</Warning>

<Tabs>
  <Tab title="Installed CLI or npx">
    The installed CLI does not read env files on its own. Create `~/.agent-canvas.env`, the same file used in [VM / Self-Hosted Installation](/openhands/usage/agent-canvas/backend-setup/vm), and make it readable only by you:

    ```bash
    touch ~/.agent-canvas.env
    chmod 600 ~/.agent-canvas.env
    ```

    Open the file in a text editor and add:

    ```bash
    export MARS_TOKEN="<your-digitalocean-token>"
    ```

    Load the file in the same command that starts Agent Canvas:

    ```bash
    source ~/.agent-canvas.env && agent-canvas
    ```

    For `npx`, replace `agent-canvas` with `npx @openhands/agent-canvas`.
  </Tab>
  <Tab title="Docker">
    Create `~/.agent-canvas.env` as shown in the Installed CLI tab. Load it, then pass `MARS_TOKEN` to the container by name. With `-e MARS_TOKEN` and no value, Docker copies the value from your shell, so the token does not appear in the command:

    ```bash
    source ~/.agent-canvas.env
    mkdir -p ~/projects

    docker run -it --rm \
      -p 127.0.0.1:8000:8000 \
      -e MARS_TOKEN \
      -v openhands-data:/home/openhands/.openhands \
      -v ~/projects:/projects \
      ghcr.io/openhands/agent-canvas:latest
    ```

    Open `<secret-hidden>/canvas`. The named volume keeps Agent Canvas settings, but `MARS_TOKEN` is still loaded from your environment each time you create the container. See [Install Agent Canvas](/openhands/usage/agent-canvas/setup#install-and-run) for more Docker setup details and Windows commands.
  </Tab>
  <Tab title="From source (npm run dev)">
    `npm run dev` reads a `.env` file in the repository root automatically. In your clone of the [OpenHands repository](https://github.com/OpenHands/OpenHands), add:

    ```ini
    MARS_TOKEN=<your-digitalocean-token>
    ```

    Then start Agent Canvas:

    ```bash
    npm install
    npm run dev
    ```

    The repository's `.gitignore` excludes `.env`. Do not commit it or copy the token into `.env.sample`.
  </Tab>
</Tabs>

When the token expires or you revoke it, replace `MARS_TOKEN` and restart Agent Canvas.

## Troubleshooting

| Message or symptom | What to do |
|--------------------|------------|
| **No Providers option in Add Backend** | Update Agent Canvas to version 1.28.0 or later. If you manage the server, confirm it did not explicitly disable the integration with `MARS_WEB=0`. |
| **Linux: unable to open database file** | Use the named settings volume in the Docker example instead of binding `~/.openhands`. |
| **Asked for a DigitalOcean token after restarting Docker** | This is expected because tokens entered in the browser UI are held in server memory only. Enter the token again, or [supply `MARS_TOKEN` at startup](#optional-sign-in-automatically-after-restarts). OAuth is not available in the browser UI. |
| **Could not connect to DigitalOcean.** | Copy the token again and check that it has not expired. If you load it from an env file, check that the value has no extra spaces and that the file is loaded before Agent Canvas starts. |
| **DigitalOcean refused the connection.** | Create a new token with **Full Access**, and confirm your team can use Managed Agents. |
| **This DigitalOcean sign-in has expired.** | Create a new token and sign in again. |
| **This team has no OpenHands agents yet.** | Select **New Agent**. Agents for other harnesses are hidden. |
| **This session isn't running an OpenHands agent server…** | The session was not started from an OpenHands agent. Launch a session from an agent created in Agent Canvas. |
| **Could not launch a new session.** | Stop sessions you no longer need, and check that your DigitalOcean balance is above $0. |
| **A session stays on Waking the session…** | Add funds to your DigitalOcean account. Sessions stay paused at a $0 balance. |
| **Your system keychain is unavailable…** | Unlock or install a keychain (common on Linux), or sign in again each time you open the app. |
| **Conversations fail right after connecting** | Add an LLM profile in **Settings → LLM**, then try again. |
