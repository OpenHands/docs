# Agent Canvas 1.36.0

Released November 5, 2026.

[View the full release on GitHub](https://github.com/OpenHands/OpenHands/releases/tag/v1.36.0).

## Highlights

- **Automation templates respond to your setup** — Suggested starts with proven templates when nothing is connected, promotes templates for connected providers and installed MCP servers, and shows up to eight cards. Jira Data Center and Bitbucket Data Center templates remain in the catalog on all backends, with placement based on available connections. On self-hosted instances without a detected Git connection, a Git template can guide you to MCP or token setup before opening. See [Pre-built Automations](/openhands/usage/agent-canvas/prebuilt-automations).
- **Data Center template repository picker** — The Bitbucket Data Center code review and Jira Data Center issue-to-Bitbucket Data Center PR templates offer a repository picker when a Bitbucket Data Center connection and host are available. A pick is included in the automation's `repos` only when the automation service reports that it can clone that provider; otherwise, the template prompt still names the repository. See [Repository picker providers](/openhands/usage/agent-canvas/managing-automations#repository-picker-providers).
- **Enterprise Git onboarding** — The first Enterprise Super Admin's setup guide adds `Connect Git` after `Add an LLM`, with a GitHub MCP install tour and a built-in OAuth-app alternative. This is distinct from the local Agent Canvas first-time wizard. See [Docker Compose onboarding](/enterprise/docker-compose#install).
- **Service-account run identity** — On supported Enterprise deployments, automation managers can choose a service account in `Runs as`. The detail view distinguishes the account that runs the automation from the person who created it; edit and tag permissions depend on the run identity. See [Enterprise Automations](/enterprise/automations).
- **Automation setup stays in the form** — The setup assistant proposes fields for review rather than creating the automation through the API, and cloud-backed drafts can be saved and reopened. See [Create an automation with the setup assistant](/openhands/usage/agent-canvas/managing-automations#create-an-automation-with-the-setup-assistant).
- **Consistent automation layout** — Setup and detail pages share header styling. Schedule controls wrap on narrow screens; script bundle file rows start collapsed, and Load more reveals all fetched run-history entries.

## Fixes

- GitHub OAuth connections without a GitHub App installation can list repositories directly; installation-backed connections retain their existing path.
- Stop and live activity appear on the first ACP turn after a fresh connection; a saved Thinking group opens its reasoning on the first click.
- Saved conversation history ending in a Stop hook no longer shows a false error toast.
- Windows local workspaces show files in the Files tab and accept valid drive-letter paths for Planner's `PLAN.md`.
- Choosing an ACP agent on a local backend no longer writes agent settings prematurely.
- Template cards and Data Center event pills show their provider logos.

## Maintenance

- Updated bundled agent-server to `1.60.1` and `@openhands/extensions` to `0.41.0`.
- Updated Node in CI, desktop bundle, and Docker to `24.22.1`; dependency, lint, and test maintenance also shipped.
