## What are Organizations?

Organizations allow multiple users to collaborate within a shared workspace in OpenHands Cloud or OpenHands Enterprise. With
Organizations, teams can share a pool of credits, use consistent LLM configurations, and streamline access
to repositories.

<Note>
  Organizations is a commercial feature available with an OpenHands Cloud subscription or OpenHands Enterprise.

  **If you are interested in a commercial subscription, please contact [OpenHands Sales](https://www.openhands.dev/contact).**
</Note>

## Key Features

Organizations provide the following capabilities:

- **Multiple Users** - Add team members to a common organization for centralized management.
- **Shared Credits** - Pool OpenHands Cloud credits across all organization members.
- **Default LLM Configuration** - Define the default model provider and LLM that all members can use.
- **Git Organization Claiming** - Claim specific Git organizations to route OpenHands resolver requests to your organization.

## Key Concepts

### Personal Workspaces and Team Organizations

Every user has a **personal workspace**, created automatically the first time they sign in. It is a private
organization for one person. Conversations, secrets, API keys, and automations created while it is the current
organization belong to it.

A **team organization** is one you create on purpose to share resources. It has members with
[roles](/openhands/usage/cloud/organizations/roles-permissions), a default LLM configuration, shared credits,
and optional Git organization claims. A user can belong to their personal workspace and any number of team
organizations at the same time.

### Current Organization

Each user has one **current organization**. It decides where new conversations are created and which settings
apply. Switch between organizations from the organization selector in the app. The selector is hidden when
there is only one organization to choose from.

OpenHands remembers each user's last selection. Requests that do not name an organization use it, for example
API calls made with an API key that is not tied to an organization.

### Super Admins

<Note>
  Super admins apply to OpenHands Enterprise.
</Note>

A **super admin** is an instance-level role, separate from the organization roles `Owner`, `Admin`, and `Member`.
A super admin can create organizations, invite or provision users into them, grant or revoke the super admin
role, and set organization quotas. A super admin does not get organization-level permissions in organizations
it is not a member of, and is not added as a member of the organizations it creates.

On OpenHands Enterprise, only super admins can create organizations. To find your super admin or add more, see
the [Super Admins and Organizations](/cookbook/org-admin) cookbook example.

### Default Organization

<Note>
  The default organization applies to OpenHands Enterprise.
</Note>

A **default organization** is an optional team organization that an administrator turns on for the whole
installation. It can add every user who signs in to the same organization as a member, and can hide personal
workspaces so it is the only workspace users see.

Existing data is never deleted when you turn these settings on or off. See
[Configuring Organizations](/openhands/usage/cloud/organizations/configuring-organizations) for the settings,
what each one does, and how to move an existing installation to organizations.

## Conversation Visibility

By default, conversations remain **private to individual members** of an organization. Each user's conversations
are only visible to them. 

## Getting Started

To start using Organizations:

1. Subscribe to an OpenHands Cloud plan or OpenHands Enterprise.
2. Create a new organization. In OpenHands Cloud, use the dashboard. In OpenHands Enterprise, a [super admin](#super-admins) creates it. See [Configuring Organizations](/openhands/usage/cloud/organizations/configuring-organizations).
3. [Invite team members](/openhands/usage/cloud/organizations/managing-members) to join your organization.
4. Configure your organization's [LLM settings](/openhands/usage/cloud/organizations/settings) and shared resources.
