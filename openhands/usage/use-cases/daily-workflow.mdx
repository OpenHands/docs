Instead of manually browsing issue trackers, Slack channels, and GitHub notifications, you can have an AI agent gather, organize, and prioritize everything for you — then work through tasks one at a time without leaving the conversation.

This use case walks through the workflow demonstrated in the video above, showing how to orchestrate an entire daily development routine through the OpenHands Agent Canvas.

## Overview

The daily workflow follows a three-phase loop:

1. **Gather** — The agent connects to your task management, communication, and code platforms via MCP, then collects all pending items: PRs awaiting your attention, PRs requesting review, assigned issues, Slack highlights, and GitHub notifications.
2. **Prioritize** — The agent produces a structured report organized by urgency, then gives you one task at a time so you're not overwhelmed by the full list.
3. **Execute** — You work on the task (or dispatch a subagent to handle it). When finished, you ask for the next issue. On good days, you never leave the agent interface.

## Step-by-Step Walkthrough

### Step 1: Connect Your Tools via MCP

The agent needs access to your external tools. In the OpenHands Agent Canvas, navigate to **MCPs** to add connections:

**GitHub:**
1. Go to GitHub → Settings → Developer Settings → Personal Access Tokens → Fine-grained tokens
2. Generate a token scoped to your organization (e.g., `OpenHands`)
3. Select the repositories you want the agent to access
4. Grant permissions: **content** (read), **pull requests** (read/write), **issues** (read/write), **workflows** (read)
5. Paste the token into the Agent Canvas MCP configuration

**Slack:**
1. Get your Slack team ID from your workspace URL
2. Set up a Slack bot (e.g., via the Slack API)
3. Connect it to your workspace and select the channels to monitor
4. Grab the bot token and add it to the Agent Canvas MCP configuration

<Note>
You can also use other tools — Linear, Jira, GitLab, Bitbucket, or Microsoft Teams — by configuring the appropriate MCP connections. The workflow is the same regardless of which tools you use.
</Note>

### Step 2: Run the Daily Workflow

With your tools connected, trigger the workflow by telling the agent:

```
Do my daily workflow.
```

If you have the [daily-workflow skill](https://github.com/OpenHands/extensions/tree/main/skills/daily-workflow) installed, the agent will automatically know what to do: gather tasks from all connected sources, organize them, and produce a structured report.

You can also customize the instructions. For example, to limit scope or change the output format:

```
Do my daily workflow, but only use your MCP tools for GitHub and Slack.
At the end, give me a structured report of all of the things to do today,
and then give me my first task to do.
```

The key insight: **skills provide a reusable base that you can diverge from**. You don't need to re-explain the entire workflow each time — just specify what's different.

### Step 3: Review the Structured Report

After a few minutes, the agent returns a structured report. A typical report includes:

| Category | Example Items |
|----------|--------------|
| **Immediate Action** | CI is stuck on a PR — needs a fix to unblock the team |
| **PRs Awaiting Your Attention** | Changes requested on a 623-line PR that a team is waiting on |
| **PRs Requesting Your Review** | Two PRs from teammates needing review |
| **Assigned Issues** | Three GitHub issues assigned to you |
| **Slack Highlights** | Important mentions or threads requiring a response |
| **GitHub Notifications** | Workflow failures, mentions, or assignment notifications |

The agent then gives you **one task at a time** — the highest-priority item — so you can focus without being overwhelmed by the full list.

### Step 4: Work Through Tasks

For each task the agent presents:

1. **Ask for links** — Say "give me links to those" and the agent provides clickable URLs to the PR, issue, or Slack thread
2. **Start working** — Click through and begin the task, or ask the agent to handle it directly
3. **Dispatch subagents** — For parallelizable work, start a background agent to remediate failing CI or address review comments on your other open PRs
4. **Move to the next task** — When finished, say "I finished those. Give me the next issue to work on."

The agent can also **dispatch subagents** via the Agent Canvas to work on remediation in parallel:

```
Dispatch another agent to remediate all failing CI and
unaddressed review comments on my open PRs.
```

This lets you focus on high-priority work while the subagent handles routine fixes in the background.

### Step 5: Automate the Morning Run

Instead of waiting for the workflow to run interactively, set up an [OpenHands Automation](/openhands/usage/automations/overview) to trigger it at the start of each day:

```
Create an automation that runs my daily workflow at 6 AM every work day.
```

When you start working, the structured report is already waiting for you — no waiting required.

## Key Technical Details

### MCP Tool Permissions

The agent's effectiveness depends on having the right MCP permissions configured:

| Tool | Required Permissions |
|------|---------------------|
| **GitHub** | `content:read`, `pull_requests:read+write`, `issues:read+write`, `workflows:read` |
| **Slack** | `channels:history`, `channels:read`, `chat:write` (for posting updates) |
| **Linear** (optional) | `read` access to issues, assignments, and cycle information |

### Skills as Reusable Workflows

The daily-workflow skill encapsulates the entire triage process. Once installed in your workspace (`/add-skill`), the agent knows how to:

- Query all connected MCP tools for pending items
- Categorize and prioritize results
- Format a structured report
- Present tasks one at a time

You can customize the skill's behavior by modifying the instructions in the prompt — the skill provides the base, and you override specific behaviors as needed.

### Subagent Dispatch

The Agent Canvas supports dispatching subagents — separate agent conversations that run in the background. This is useful for:

- **CI remediation** — Fix failing builds on PRs you're not actively working on
- **Review comment resolution** — Address "changes requested" feedback on older PRs
- **Parallel task execution** — Work on multiple issues simultaneously

## Automate This

### Option A: OpenHands Automation (Scheduled)

Set up a cron-based automation to run the daily workflow at a fixed time each day. In [OpenHands Cloud](https://app.all-hands.dev), create an automation with:

```
Create an OpenHands Cloud automation using the Skill Preset:

**Name:** Daily Workflow
**Skill:** daily-workflow
**Trigger:** schedule (cron: 0 6 * * 1-5)
**Instructions:** Gather all pending tasks from GitHub and Slack.
Produce a structured report organized by urgency.
Present the first task to work on.
```

### Option B: Manual Trigger

Run the workflow on demand in any OpenHands conversation:

```
/add-skill https://github.com/OpenHands/extensions/tree/main/skills/daily-workflow
```

Then:

```
Do my daily workflow.
```
