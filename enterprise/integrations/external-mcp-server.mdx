---
title: External MCP Server
description: Connect an approved MCP client to self-hosted OpenHands Enterprise to start tasks, check their progress, and send follow-ups.
---

Use the External MCP Server to work with OpenHands tasks from an MCP client such as Claude Code. For example, ask the
client to start a task in a Git repository, check back for the result, and open the same task in Agent Canvas.

The server is available in OpenHands Enterprise app version **1.96.0 and later**. A Super Admin enables access, and
each user signs in to OpenHands and approves the client. The client can access only the user's own V1 tasks in the
organization they connect.

## Available Tools

| Tool | OAuth scope | What you can do |
| --- | --- | --- |
| `list_my_tasks` | `tasks:read` | List recent top-level tasks with their IDs, titles, and Agent Canvas links. The default is 10 tasks, with a maximum of 20. |
| `get_task` | `tasks:read` | Get the status of a task by ID and read its result when available. |
| `start_task` | `tasks:write` | Start a task with a prompt. For a Git repository you can access through a connected provider, pass `repository` as `owner/name` and optionally pass `branch`. The tool returns the task ID and Agent Canvas link while the task runs in the background. |
| `send_message` | `tasks:write` | Send a follow-up to an existing task by ID. Use `get_task` again to check for the agent's response. |

## Set Up OpenHands Enterprise

Use the HTTPS URL of your OpenHands instance. For an instance at `https://openhands.example.com`, the Streamable HTTP
endpoint is `https://openhands.example.com/external-mcp/mcp`.

### Register an OAuth Client

Set `OPENHANDS_EXTERNAL_MCP_CLIENTS` to a JSON array with an entry for each approved client. The example registers a
read-only Claude Code client in Helm's `env` map. On Docker Compose, set the same JSON array as an environment variable.
See [Set a Variable](/enterprise/environment-variables#set-a-variable).

```yaml values.yaml
env:
  OPENHANDS_EXTERNAL_MCP_CLIENTS: |-
    [
      {
        "client_id": "openhands-demo",
        "name": "Claude Code",
        "redirect_uris": ["http://localhost:53682/callback"],
        "scopes": ["tasks:read"]
      }
    ]
```

- Register the exact callback URL the client uses. Use HTTPS for remote callbacks or HTTP for loopback callbacks such as
  `http://localhost:53682/callback`.
- For a public client such as a local CLI, omit `client_secret` and use PKCE with `S256`. For a confidential client,
  store its `client_secret` in your deployment's secrets and configure the client to use `client_secret_post`.
- Include `tasks:read` for every client. Add `tasks:write` only for clients that need to start tasks or send follow-ups.

Apply the configuration and let the OpenHands application restart. The server uses the instance web URL with
`/external-mcp` appended as its OAuth issuer. If you need to override the issuer, set
`OPENHANDS_EXTERNAL_MCP_BASE_URL` to an HTTPS URL ending in `/external-mcp`.

### Enable User Access

The `ENABLE_EXTERNAL_MCP` feature flag is off by default. To enable access for a pilot user, use the following Admin API
requests with an OpenHands API key from a [Super Admin](/enterprise/super-admin) account. Send the key in the
`Authorization: Bearer` header. Replace the example user and organization IDs. If the flag already exists, review its
rules before changing access.

| Step | Request | JSON body |
| --- | --- | --- |
| 1. Check for an existing flag | `GET /api/admin/feature-flags/ENABLE_EXTERNAL_MCP` | None |
| 2. If the flag returns `404`, create it disabled | `POST /api/admin/feature-flags` | `{"key":"ENABLE_EXTERNAL_MCP","enabled":false}` |
| 3. Include the pilot user in the organization | `POST /api/admin/feature-flags/ENABLE_EXTERNAL_MCP/rules` | `{"effect":"include","org_id":"ORG_ID","user_id":"USER_ID"}` |
| 4. Enable the flag | `PATCH /api/admin/feature-flags/ENABLE_EXTERNAL_MCP` | `{"enabled":true}` |
| 5. Verify access for the pilot user | `POST /api/admin/feature-flags/ENABLE_EXTERNAL_MCP/evaluate` | `{"org_id":"ORG_ID","user_id":"USER_ID"}` |

The evaluation should return `{"enabled":true}` for the pilot user. Repeat it with a user outside the pilot to verify
that it returns `{"enabled":false}`. Omit `user_id` from the include rule to grant access to the entire organization.

For deployment-wide access, set the environment variable `ENABLE_EXTERNAL_MCP=true` if you have no database flag of
the same name. If the database flag exists, its enabled state and rules control access.

### Check OAuth Discovery

Run this request against your instance. The response should be JSON with `resource` set to your MCP endpoint URL.

```bash
curl -fsS https://openhands.example.com/.well-known/oauth-protected-resource/external-mcp/mcp
```

If you get a `404` or an HTML response, check the client registration and HTTPS instance URL. If you use a reverse proxy
with path-based routing, forward `/external-mcp/*` and both OAuth discovery paths to the OpenHands application.

- `/.well-known/oauth-protected-resource/external-mcp/mcp`
- `/.well-known/oauth-authorization-server/external-mcp`

If you need OpenAI app domain verification, set `OPENAI_APPS_CHALLENGE_TOKEN` to the issued token and forward
`/.well-known/openai-apps-challenge` to the application. The path should return the token as plain text.

## Connect Claude Code

1. Add the `openhands` entry to the `.mcp.json` file in your project. Use your instance URL and the client ID and
   loopback port registered by your Super Admin.

   ```json .mcp.json
   {
     "mcpServers": {
       "openhands": {
         "type": "http",
         "url": "https://openhands.example.com/external-mcp/mcp",
         "oauth": {
           "clientId": "openhands-demo",
           "callbackPort": 53682,
           "scopes": "tasks:read"
         }
       }
     }
   }
   ```

2. Sign in to OpenHands in your browser and switch to the organization you want to connect. Launch `claude` from the
   project and approve the project configuration if prompted. Run `/mcp`, select `openhands`, and authenticate. Approve
   the requested access in your browser.
3. Ask Claude Code to list your tasks.

   > Use `list_my_tasks` on the OpenHands MCP server to show my five most recent tasks with their links.

To start a task or send a follow-up, have your Super Admin add `tasks:write` to the client registration. Set
`oauth.scopes` to `tasks:read tasks:write`, then reconnect and approve the updated access. Try asking Claude Code to
start a task that summarizes the README in a repository you can access. Use `get_task` with the returned ID to check its
status and result.

For more client configuration options, see the
[Claude Code MCP documentation](https://code.claude.com/docs/en/mcp#use-pre-configured-oauth-credentials).

## Connect Another MCP Client

Use a client that supports Streamable HTTP and OAuth with a pre-registered client ID and callback URL. Give the client
the MCP endpoint URL, use that exact URL as the OAuth resource, and request `tasks:read` plus `tasks:write` if needed.
Sign in and approve the connection in OpenHands.
