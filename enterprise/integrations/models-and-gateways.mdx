## How do you want to manage your models and budgets?

OpenHands can call your model provider directly or send inference requests through a gateway.
Your choice determines where you set spending limits and which usage reports you can use.

### 1. Bundled LiteLLM — set budgets and review usage in OpenHands

Use bundled LiteLLM if you want a gateway integrated with OpenHands Enterprise and don't already
run one. Once you configure it, organization admins can set
[organization and per-member budgets](/openhands/usage/cloud/organizations/budgets) and review usage
in OpenHands. LiteLLM enforces the limits.

- **Helm.** Enable and configure bundled LiteLLM in the
  [installation values](/enterprise/k8s-install/installation#step-2-configure-values).
- **Docker Compose.** Add the optional
  [Compose LiteLLM overlay](https://github.com/OpenHands/enterprise/blob/main/docs/compose-litellm.md).
- **Replicated.** Configure your provider in the
  [Admin Console](/enterprise/vm-install/admin-console-configuration#llm-configuration).

### 2. Connect directly and manage spend with your inference provider

Connect to a provider such as OpenAI, Anthropic, or Amazon Bedrock using your provider credentials.

- **Docker Compose.** Follow [Compose onboarding](/enterprise/docker-compose) for providers that use
  an API key.
- **Helm.** If your deployment allows custom provider settings, select a direct provider profile.
  The agent sandbox needs access to the provider endpoint and its credentials. For Bedrock, the
  published [Helm recipe](/enterprise/integrations/aws-bedrock-llm-gateway) configures the bundled
  gateway to call AWS.

OpenHands can still show conversation tokens and estimated cost. Direct calls bypass the
organization and per-member budget limits in OpenHands.

### 3. Use your own external gateway

If you already run a gateway, choose how OpenHands should connect to it:

- [**Forward through bundled LiteLLM**](/enterprise/integrations/external-llm-gateways). Set
  budgets in OpenHands. Bundled LiteLLM forwards
  inference to your gateway using a credential configured by an admin.
- [**Use per-member keys**](/enterprise/integrations/customer-llm-gateway). OpenHands calls
  your gateway with each member's existing virtual key. Your gateway records spend and
  enforces limits for that key.

The per-member relay uses the OpenAI-compatible Chat Completions API and a configurable credential
header. The per-member guide covers Docker Compose and Helm with the OpenHands Runtime API, using
LiteLLM as the validated example. For other gateways, verify authentication, spend attribution, and
limits for each member’s key.
