OpenHands Enterprise reads its configuration from environment variables. Each table lists the default that
OpenHands uses when you don't set the variable. The Helm chart and the Docker Compose stack set many of these
variables for you, so your installation can use a different value.

Set boolean variables to `true` or `false`.

## Set a Variable

<Tabs>
  <Tab title="Helm">
    Many variables have a dedicated value in the Helm chart, such as `smtp.host` or `github.enabled`, and the chart
    sets the variable for you. See the chart's
    [configuration reference](https://github.com/OpenHands/OpenHands-Cloud/blob/main/charts/openhands/README.md#configuration)
    for those values.

    To set any variable on this page directly, add it under `env` in your values and apply them with
    `helm upgrade`. An `env` entry takes precedence over the value that the chart sets for the same variable.

    ```yaml values.yaml
    env:
      LOG_LEVEL: DEBUG
    ```
  </Tab>
  <Tab title="Docker Compose">
    Set variables in a `.env` file next to `docker-compose.yml`, then run `docker compose up --wait`.

    ```bash .env
    WEB_HOST=openhands.example.com
    WEB_URL=https://openhands.example.com
    AGENT_CANVAS_LOCK_TO_CLOUD=https://openhands.example.com
    ```

    `docker-compose.yml` sets its own values for some variables, such as `DB_HOST` and `WEB_HOST`. A value that
    `docker-compose.yml` sets explicitly takes precedence over `.env`. To change one of those, add it to a
    `docker-compose.override.yml`. Set `DB_NAME`, `DB_USER`, and `DB_PASS` before the first start, because
    PostgreSQL creates the database and user only once.

    These variables configure the stack itself:

    | Variable | Default | Description |
    | --- | --- | --- |
    | `APP_PORT` | `9043` | Port on the host that serves the stack. |
    | `WEB_URL` | `http://localhost:<APP_PORT>` | Full URL that users open, including the scheme and any port. The stack passes it to OpenHands as `OH_WEB_URL`. |
    | `AGENT_CANVAS_LOCK_TO_CLOUD` | `http://localhost:<APP_PORT>` | URL that Agent Canvas connects to. Set it to the same value as `WEB_URL`. |
    | `COMPOSE_FILE` | None | Compose files to load, separated by colons. Use it to add the [HTTPS overlay](/enterprise/docker-compose/https). |
    | `AUTOMATION_SERVICE_KEY` | Placeholder | Key that OpenHands and the automation service share. The stack passes it to OpenHands as `AUTOMATIONS_SERVICE_KEY`. |
    | `AUTOMATION_KV_SECRET` | Placeholder | Key that signs automation KV tokens and encrypts the state that automations store. |
    | `AUTOMATION_DB_NAME` | `automations` | Database for the automation service. |
    | `APP_IMAGE`<br />`AUTOMATION_IMAGE`<br />`AGENT_CANVAS_IMAGE` | Release image | Images for OpenHands, the automation service, and Agent Canvas. |
  </Tab>
</Tabs>

## General

| Variable | Default | Description |
| --- | --- | --- |
| `WEB_HOST` | `app.all-hands.dev` | Hostname that users open OpenHands on, without a scheme, such as `openhands.example.com`. OpenHands uses it in links in emails and integration comments. |
| `OH_WEB_URL` | `https://<WEB_HOST>` | Full URL that users open, including the scheme and any port. OpenHands uses it for sign-in redirects and cookies. The default uses `http://` when `WEB_HOST` is `localhost`. |
| `OH_SANDBOX_WEB_URL` | `OH_WEB_URL` | URL that sandboxes use to reach OpenHands, when it differs from `OH_WEB_URL`. It must serve the same routes. |
| `PERMITTED_CORS_ORIGINS` | `https://<WEB_HOST>` | Comma-separated origins that can call the API from a browser. |
| `CONTENT_SECURITY_POLICY` | Built-in policy | Value of the `Content-Security-Policy` header. Set an empty value to remove the header. |
| `LOG_LEVEL` | `INFO` | Log level: `DEBUG`, `INFO`, `WARNING`, or `ERROR`. |
| `MAINTENANCE_START_TIME` | None | Start of planned maintenance, as an ISO 8601 timestamp. When set, OpenHands shows a maintenance banner. |

## License

| Variable | Default | Description |
| --- | --- | --- |
| `OPENHANDS_LICENSE_KEY` | None | License key from Customer Center. When set, it replaces a license that a Super Admin added in the app, and the app doesn't let anyone change the license. |
| `OPENHANDS_OFFLINE_LICENSE` | None | Contents of an offline license file from Customer Center, for installations that can't reach Customer Center. When set, OpenHands ignores `OPENHANDS_LICENSE_KEY`. |
| `OPENHANDS_OFFLINE_LICENSE_FILE` | None | Path to an offline license file. Set this variable or `OPENHANDS_OFFLINE_LICENSE`, not both. |
| `LICENSE_SERVER_URL` | `https://customercenter.openhands.dev` | Customer Center URL. |
| `LICENSE_CHECK_INTERVAL_SECONDS` | `1800` | Seconds between license checks against Customer Center. The minimum is `60`. |

## Database

For production, we recommend your own PostgreSQL. See [External PostgreSQL](/enterprise/external-postgres).

| Variable | Default | Description |
| --- | --- | --- |
| `DB_HOST` | None | Hostname of PostgreSQL. Required. |
| `DB_PORT` | `5432` | Port of PostgreSQL. |
| `DB_NAME` | `openhands` | Application database. |
| `DB_USER` | `postgres` | Database user. |
| `DB_PASS` | `postgres` | Database password. |
| `DB_SSL_MODE` | `prefer` | SSL mode: `prefer`, `require`, or `disable`. `require` doesn't verify the server certificate. |
| `DB_POOL_SIZE` | `25` | Connections in each database connection pool. |
| `DB_MAX_OVERFLOW` | `10` | Connections that each pool can open above `DB_POOL_SIZE`. |
| `RUN_MIGRATIONS_ON_STARTUP` | `false` | Migrate the database schema when OpenHands starts. |
| `CREATE_DATABASE_IF_MISSING` | `false` | Create `DB_NAME` before migrating, if it doesn't exist. The database user needs the `CREATEDB` privilege. |

## Conversation Storage

Use an S3-compatible store, Google Cloud Storage, or a local directory. Google Cloud Storage uses the workload's
service account. For Amazon S3 on EKS, see [object storage](/enterprise/k8s-install/eks#object-storage).

| Variable | Default | Description |
| --- | --- | --- |
| `FILE_STORE` | `local` | Storage backend: `s3`, `google_cloud`, or `local`. |
| `FILE_STORE_PATH` | `/.openhands` | Bucket for `s3` and `google_cloud`, or the directory for `local`. |
| `AWS_S3_ENDPOINT` | Amazon S3 | Endpoint of an S3-compatible store other than Amazon S3, such as `s3.example.com`. |
| `AWS_S3_SECURE` | `true` | Connect to `AWS_S3_ENDPOINT` over HTTPS. Set it to `false` to connect over HTTP. |
| `AWS_ACCESS_KEY_ID`<br />`AWS_SECRET_ACCESS_KEY` | None | Access key pair for S3. When unset, OpenHands uses the workload's AWS identity. |

## Authentication

| Variable | Default | Description |
| --- | --- | --- |
| `JWT_SECRET` | Generated | Key that signs session tokens and encrypts the secrets that OpenHands stores. When unset, OpenHands generates a key on the first start and saves it in `FILE_STORE_PATH`. Every replica must use the same key. Don't change it after the first start, because OpenHands can't read secrets that it stored with a different key. |
| `ENABLE_INTEGRATED_IDP` | `false` | Add email and password sign-in. OpenHands reads it once, when it first sets up the database. After that, a Super Admin manages password sign-in under `Auth Providers`. |
| `SUPER_ADMIN_EMAILS` | None | Comma-separated email addresses that get the Super Admin role when they sign in through an auth provider. Requires `ENABLE_OAUTH_V2_LOGIN`. |
| `DUPLICATE_EMAIL_CHECK` | `true` | Reject a Keycloak sign-up when another account has the same email address after its plus-address suffix is removed, such as `name+test@example.com`. |
| `REQUIRE_VERIFIED_EMAILS` | `false` | Block users whose email address isn't verified. |
| `EMAIL_CHANGE_ENABLED` | `true` | Let users change their email address. |

## LLM

By default, OpenHands routes LLM requests through a LiteLLM proxy, which manages each user's key and budget. See
[LLM Gateways](/enterprise/integrations/external-llm-gateways) for provider examples.

| Variable | Default | Description |
| --- | --- | --- |
| `ENABLE_LEGACY_LITELLM` | `true` | Route LLM requests through the LiteLLM proxy. Set it to `false` to have users add their own LLM keys. |
| `LITE_LLM_API_URL` | `https://llm-proxy.app.all-hands.dev` | URL of your LiteLLM proxy. |
| `LITE_LLM_API_KEY` | None | Master key of the LiteLLM proxy. |
| `LITE_LLM_TEAM_ID` | None | LiteLLM team for new users. |
| `LITELLM_DEFAULT_MODEL` | Release's default model | Default model for new users and organizations, such as `litellm_proxy/claude-sonnet-4-5`. |

To give every new user the same model and key without LiteLLM, set `OPENHANDS_LLM_PROVIDER_ROUTE` to `direct`:

| Variable | Default | Description |
| --- | --- | --- |
| `OPENHANDS_LLM_PROVIDER_ROUTE` | None | Set it to `direct` to give new users and organizations the model, base URL, and key below. Requires `OPENHANDS_DEFAULT_LLM_MODEL`. |
| `OPENHANDS_DEFAULT_LLM_MODEL` | None | Model for new users and organizations. |
| `OPENHANDS_DEFAULT_LLM_BASE_URL` | Provider's URL | Base URL of the model's API. |
| `OPENHANDS_DEFAULT_LLM_API_KEY` | None | API key that OpenHands copies into each new user's LLM settings. |

## Sandboxes

| Variable | Default | Description |
| --- | --- | --- |
| `RUNTIME` | Docker | Set it to `remote` to run sandboxes through the Runtime API. When unset, OpenHands runs sandboxes as containers on the host's Docker engine. |
| `OH_APP_CONVERSATION_SANDBOX_GROUPING_STRATEGY` | `NO_GROUPING` | How OpenHands places a new conversation. `NO_GROUPING` starts a new sandbox for each conversation. `FEWEST_CONVERSATIONS`, `GROUP_BY_NEWEST`, `LEAST_RECENTLY_USED`, and `ADD_TO_ANY` add it to one of the user's running sandboxes. User and organization settings override it. |
| `OH_APP_CONVERSATION_MAX_NUM_CONVERSATIONS_PER_SANDBOX` | `20` | Maximum number of conversations that OpenHands adds to one sandbox. |
| `OH_APP_CONVERSATION_SANDBOX_STARTUP_TIMEOUT` | `120` | Seconds that a conversation waits for its sandbox to start. |

### Runtime API

These variables apply when `RUNTIME` is `remote`. The Runtime API sets the sandbox image and environment. For
sandbox CPU and memory on Kubernetes, see [Resource Limits](/enterprise/k8s-install/resource-limits).

| Variable | Default | Description |
| --- | --- | --- |
| `SANDBOX_REMOTE_RUNTIME_API_URL` | None | URL of the Runtime API. Required. |
| `SANDBOX_API_KEY` | None | Key that OpenHands uses to call the Runtime API. Required. |
| `OH_SANDBOX_MAX_NUM_SANDBOXES` | `10` | Maximum number of sandboxes that each user can run at once. When a user starts another sandbox, OpenHands pauses their oldest running one. |
| `OH_DAILY_SANDBOX_LIMIT` | No limit | Maximum number of sandboxes that each user can create per day, in UTC. |
| `OH_HTTPX_TIMEOUT` | `15` | Seconds that OpenHands waits for a response from the Runtime API and other services. |

### Docker

These variables apply when `RUNTIME` is unset.

| Variable | Default | Description |
| --- | --- | --- |
| `AGENT_SERVER_IMAGE_REPOSITORY` | `ghcr.io/openhands/agent-server` | Repository of the sandbox image. See [Custom Sandbox Images](/enterprise/custom-sandbox-images/index). |
| `AGENT_SERVER_IMAGE_TAG` | `<release version>-python` | Tag of the sandbox image. With the default repository, OpenHands replaces the version in the tag with the release's version, so set `AGENT_SERVER_IMAGE_REPOSITORY` too to run a different build. |
| `OH_AGENT_SERVER_ENV` | None | Environment variables for every sandbox, as a JSON object with string values, such as `{"MY_VAR": "value"}`. |
| `SANDBOX_CONTAINER_URL_PATTERN` | `http://localhost:{port}` | URL that browsers use to reach a sandbox port. OpenHands replaces `{port}` with the port and `{sandbox_id}` with the container name. |
| `SANDBOX_DOCKER_NETWORK` | Default bridge network | Docker network for sandbox containers. When set, `SANDBOX_CONTAINER_URL_PATTERN` must include `{sandbox_id}`. |
| `SANDBOX_INTERNAL_URL` | None | URL that OpenHands uses to reach sandboxes, when it differs from the browser URL in `SANDBOX_CONTAINER_URL_PATTERN`. |
| `SANDBOX_HOST_PORT` | `3000` | Port that sandboxes use to reach OpenHands on the host, when neither `OH_SANDBOX_WEB_URL` nor `OH_WEB_URL` is set. |
| `SANDBOX_STARTUP_GRACE_SECONDS` | `15` | Seconds that a new sandbox has to respond before OpenHands marks it as failed. |
| `SANDBOX_VOLUMES` | None | Comma-separated bind mounts for every sandbox, in the form `host_path:container_path[:mode]`. |
| `SANDBOX_KVM_ENABLED` | `false` | Pass `/dev/kvm` to sandboxes. |
| `SANDBOX_PAUSE_ON_SHUTDOWN` | `false` | Pause running sandboxes when OpenHands stops. |
| `OH_SANDBOX_LIFECYCLE_IDLE_SECONDS` | `1200` | Pause a sandbox after its agent has been idle for this many seconds. Set it to `0` to turn it off. |
| `OH_SANDBOX_LIFECYCLE_MAX_SESSION_SECONDS` | `43200` | Pause a sandbox this many seconds after it starts or resumes. Set it to `0` to turn it off. |
| `OH_SANDBOX_LIFECYCLE_DELETE_AFTER_SECONDS` | `864000` | Delete a sandbox and its workspace after it hasn't run for this many seconds. Set it to `0` to turn it off. |

### Workspace Archives

With the Runtime API, OpenHands can archive a conversation's workspace to object storage before it deletes the
sandbox.

| Variable | Default | Description |
| --- | --- | --- |
| `RUNTIME_FILE_ARCHIVE_ENABLED` | `false` | Archive workspaces before OpenHands deletes their sandboxes. |
| `RUNTIME_FILE_ARCHIVE_STORE_TYPE` | `google_cloud` | Storage backend: `google_cloud`, `s3`, or `local`. `s3` uses the `AWS_*` variables in [Conversation Storage](#conversation-storage). |
| `RUNTIME_FILE_ARCHIVE_BUCKET` | None | Bucket for archives, or the directory for `local`. |
| `RUNTIME_FILE_ARCHIVE_PREFIX` | `workspace-archives` | Prefix of archive object keys. |
| `RUNTIME_FILE_ARCHIVE_FORMAT` | `both` | Archive format: `git-delta` for a Git diff, `tar.gz` for the full workspace, or `both`. |
| `RUNTIME_FILE_ARCHIVE_REQUIRED` | `false` | Keep the sandbox when its archive fails, instead of deleting it. |
| `RUNTIME_FILE_ARCHIVE_TIMEOUT` | `660` | Seconds that OpenHands waits for an archive. |
| `RUNTIME_FILE_ARCHIVE_ENRICH` | `true` | Add installed packages and runtime versions to each archive's manifest. |

Each flag also has a structured form: `OH_WEB_CLIENT_FEATURE_FLAGS_` followed by the name without any `OH_` prefix,
such as `OH_WEB_CLIENT_FEATURE_FLAGS_HIDE_BILLING_PAGE`. When any structured flag is set, OpenHands ignores the
names in this table for the app and uses the default for each structured flag that you don't set. The Docker
Compose stack sets structured flags, so use the structured form there. In that case, set both forms of
`ENABLE_SUPER_ADMIN` and `HIDE_PERSONAL_WORKSPACES`, because the server reads the names in this table.
