Use this page to look up a setting for the [Docker Compose](/enterprise/docker-compose) stack or
the [Helm chart](/enterprise/k8s-install/installation). Each row lists the environment variable,
the equivalent Helm value, and any default. When the two deployments use different defaults, the
row lists both.

## Set a Value

<Tabs>
  <Tab title="Docker Compose">
    Set variables marked <Badge size="sm" color="blue">.env</Badge> in a `.env` file next to `docker-compose.yml`:

    ```bash .env
    WEB_HOST=openhands.example.com
    WEB_URL=https://openhands.example.com
    AGENT_CANVAS_LOCK_TO_CLOUD=https://openhands.example.com
    ```

    Set any other variable on the `app` and `worker` services in `docker-compose.override.yml`:

    ```yaml docker-compose.override.yml
    x-openhands-env: &openhands-env
      GITLAB_HOST: gitlab.example.com

    services:
      app:
        environment: *openhands-env
      worker:
        environment: *openhands-env
    ```

    Docker Compose reads `docker-compose.override.yml` automatically. If your `.env` file sets
    `COMPOSE_FILE`, add `docker-compose.override.yml` to the end of its list. Run
    `docker compose up --wait` to apply your changes.

    The stack uses placeholder passwords and keys by default. Set your own values before you share
    the stack with your team.
  </Tab>
  <Tab title="Helm">
    Set values in your `values.yaml` and apply them with `helm upgrade`. Credentials come from
    Kubernetes Secrets in the release namespace, and the table lists the Secret and key for each one.

    To set an environment variable that has no dedicated value, add it under `env`:

    ```yaml values.yaml
    env:
      LOG_LEVEL: DEBUG
    ```
  </Tab>
</Tabs>

## General

| Environment variable | Helm value | Default | Description |
| --- | --- | --- | --- |
| `WEB_HOST` <Badge size="sm" color="blue">.env</Badge> | `ingress.host` | Compose: `localhost` | Hostname that users open OpenHands on, such as `openhands.example.com`. |
| `WEB_URL` <Badge size="sm" color="blue">.env</Badge> | Set from `ingress.host` | Compose: `http://localhost:9043` | Full URL that users open, including the scheme and any port. |
| `APP_PORT` <Badge size="sm" color="blue">.env</Badge> | N/A | `9043` | Port on the host that serves the stack. |
| `AGENT_CANVAS_LOCK_TO_CLOUD` <Badge size="sm" color="blue">.env</Badge> | `agent-canvas.staticServer.lockToCloud` | Compose: `http://localhost:9043` | URL that Agent Canvas connects to. Set it to the same value as `WEB_URL`. |
| `PERMITTED_CORS_ORIGINS` | `env.PERMITTED_CORS_ORIGINS` | Compose: `http://localhost:9043`<br />Helm: `https://<WEB_HOST>` | Comma-separated origins that can call the API from a browser. |
| `COMPOSE_FILE` <Badge size="sm" color="blue">.env</Badge> | N/A | | Compose files to load, separated by colons. Use it to add the [HTTPS overlay](/enterprise/docker-compose/https). |
| `LOG_LEVEL` | `env.LOG_LEVEL` | `INFO` | Log level: `DEBUG`, `INFO`, `WARNING`, or `ERROR`. |

## License

To keep the license in a Secret that you manage on Helm, set `license.existingSecret` to a Secret
with a `license-key` or `offline-license` key.

| Environment variable | Helm value | Default | Description |
| --- | --- | --- | --- |
| `OPENHANDS_LICENSE_KEY` <Badge size="sm" color="blue">.env</Badge> | `license.key` | | License key from Customer Center. |
| `OPENHANDS_OFFLINE_LICENSE` | `license.offlineLicense` | | Contents of an offline license file from Customer Center, for installs that can't reach Customer Center. When set, OpenHands ignores the license key. On Helm, pass the file with `--set-file license.offlineLicense=<path>`. |
| `LICENSE_SERVER_URL` <Badge size="sm" color="blue">.env</Badge> | `env.LICENSE_SERVER_URL` | `https://customercenter.openhands.dev` | Customer Center URL. |

## Database and Cache

Docker Compose runs PostgreSQL and Redis as services in the stack. The Helm chart runs a bundled
PostgreSQL by default. For production, we recommend your own PostgreSQL: set
`postgresql.enabled: false`, `externalDatabase.enabled: true`, and the `externalDatabase` values
below. See [External PostgreSQL](/enterprise/external-postgres).

| Environment variable | Helm value | Default | Description |
| --- | --- | --- | --- |
| `DB_HOST` | `externalDatabase.host` | Compose: `db`<br />Helm: bundled PostgreSQL | PostgreSQL hostname. |
| `DB_PORT` | `externalDatabase.port` | `5432` | PostgreSQL port. |
| `DB_NAME` <Badge size="sm" color="blue">.env</Badge> | `externalDatabase.database`<br />`postgresql.auth.database` (bundled) | Compose: `openhands` | Application database. |
| `DB_USER` <Badge size="sm" color="blue">.env</Badge> | `externalDatabase.username`<br />`postgresql.auth.username` (bundled) | Compose: `openhands`<br />Helm: `postgres` | Database user. |
| `DB_PASS` <Badge size="sm" color="blue">.env</Badge> | Secret `postgres-password`, key `password` | Compose: placeholder | Database password. |
| `DB_SSL_MODE` | `externalDatabase.sslMode` | Helm: `prefer` | PostgreSQL SSL mode, such as `require` or `verify-full`. |
| `RUN_MIGRATIONS_ON_STARTUP` | `databaseMigrations.migrate` | `true` | Migrate the database schema when the application starts. |
| `REDIS_HOST` | `redis.enabled`<br />`valkey.enabled` | Compose: `redis`<br />Helm: bundled Redis | Redis hostname. The Helm chart runs Redis or Valkey, and Redis takes precedence when both are enabled. |
| `REDIS_PASSWORD` | Secret `redis`, key `redis-password` | Compose: none | Redis password. |

## Conversation Storage

Docker Compose stores conversation files locally. For Helm, use an S3-compatible store or Google
Cloud Storage. Google Cloud Storage uses the workload's service account. For Amazon S3 on EKS, see
[object storage](/enterprise/k8s-install/eks#object-storage).

| Environment variable | Helm value | Default | Description |
| --- | --- | --- | --- |
| `FILE_STORE` | `filestore.type` | Compose: local files<br />Helm: `gcs` | Storage backend: `s3` or `google_cloud`. The Helm value also accepts `gcs`. |
| `FILE_STORE_PATH`<br />`AWS_S3_BUCKET` | `filestore.bucket` | Helm: `openhands-sessions` | Bucket for conversation files. For S3, set both variables to the bucket name. |
| `AWS_S3_ENDPOINT` | `filestore.endpoint` | | Endpoint of an S3-compatible store other than Amazon S3. Leave it empty for Amazon S3. |
| `AWS_S3_SECURE` | Set from the `filestore.endpoint` scheme | `true` | Connect to the endpoint over HTTPS. |
| `AWS_ACCESS_KEY_ID` | `filestore.existingSecret`, key `AWS_ACCESS_KEY_ID` | | Access key ID. Leave it unset to use the workload's AWS identity. |
| `AWS_SECRET_ACCESS_KEY` | `filestore.existingSecret`, key `AWS_SECRET_ACCESS_KEY` | | Secret access key. |

## Authentication

Docker Compose signs users in with an email address and password. The Helm chart uses Keycloak,
which signs users in through your Git provider or SAML identity provider.

| Environment variable | Helm value | Default | Description |
| --- | --- | --- | --- |
| `JWT_SECRET` | Secret `jwt-secret`, key `jwt-secret` | Compose: generated on first start | Key that signs session tokens and encrypts stored secrets. |
| `DUPLICATE_EMAIL_CHECK` | `duplicateEmailCheck` | `true` | Reject a sign-in when another account has the same email address after its plus-address suffix is removed, such as `name+test@example.com`. |
| `REQUIRE_VERIFIED_EMAILS` | `env.REQUIRE_VERIFIED_EMAILS` | `false` | Reject a sign-in when the identity provider has not verified the user's email address. |
| `USER_PROVISIONING_ENABLED` | `userProvisioning.enabled` | `false` | Turn on the admin API that creates users without their input. |
| `OPEN_ORG_CREATION_ENABLED` | `openOrgCreation.enabled` | `false` | Let any signed-in user create an organization. |

## LLM

Docker Compose lets each user add their own LLM provider key in **Settings**. The Helm chart routes
LLM requests through a LiteLLM proxy. To run the bundled proxy, set `litellm-helm.enabled: true` and
store your provider keys in the `litellm-env-secrets` Secret. See
[LLM Gateways](/enterprise/integrations/external-llm-gateways) for provider examples.

| Environment variable | Helm value | Default | Description |
| --- | --- | --- | --- |
| `ENABLE_LEGACY_LITELLM` | `env.ENABLE_LEGACY_LITELLM` | Compose: `false`<br />Helm: `true` | Route LLM requests through a LiteLLM proxy, which manages each user's key and budget. |
| `LITE_LLM_API_URL` | `litellm.url` | Helm: bundled proxy when `litellm-helm.enabled` is `true` | URL of the LiteLLM proxy. |
| `LITE_LLM_API_KEY` | Secret `lite-llm-api-key`, key `lite-llm-api-key` | | Master key of the LiteLLM proxy. |
| `LITE_LLM_TEAM_ID` | `litellm.teamId` | Helm: `openhands` | LiteLLM team for OpenHands users. OpenHands creates the team if it doesn't exist. |
| `LITELLM_DEFAULT_MODEL` | `env.LITELLM_DEFAULT_MODEL` | | Default model for new users, such as `litellm_proxy/claude-sonnet-4-5`. |

## Sandboxes

Docker Compose runs sandboxes as containers on the host's Docker engine. The Helm chart runs them
through the Runtime API. For Runtime API settings, see
[Resource Limits](/enterprise/k8s-install/resource-limits).

| Environment variable | Helm value | Default | Description |
| --- | --- | --- | --- |
| `OH_SANDBOX_MAX_NUM_SANDBOXES` | `env.OH_SANDBOX_MAX_NUM_SANDBOXES` | Compose: `5`<br />Helm: `10` | Maximum number of sandboxes that each user can run at once. When a user starts another sandbox, OpenHands pauses their oldest running one. |
| `OH_AGENT_SERVER_ENV` | `global.agentServerEnv` | Compose: `{"AGENT_SERVER_PORT": "8000"}` | Environment variables for every sandbox, as a JSON object. On Helm, set a map instead. On Docker Compose, keep `AGENT_SERVER_PORT` set to `8000`. |
| `SANDBOX_REMOTE_RUNTIME_API_URL` | `sandbox.apiHostname` | | URL of the Runtime API, such as `https://runtime-api.openhands.example.com`. Helm only. |
| `SANDBOX_API_KEY` | Secret `sandbox-api-key`, key `sandbox-api-key` | | Key that the application uses to call the Runtime API. It must match the Runtime API's `default-api-key` Secret. Helm only. |
