Use this guide to turn on [Auth V2](/enterprise/auth-v2/overview) for an installation that uses V1 authentication.

Auth V2 still works with Keycloak. The providers it creates from your V1 setup keep signing users in through your
existing Keycloak client, so you don't need to change the OAuth apps or other external services you already set up.
Removing Keycloak isn't covered in this guide.

## Prerequisites

- OpenHands Enterprise 0.105.0.
- A Super Admin account.
- The Super Admin dashboard enabled. See [Super Admin Dashboard](/enterprise/super-admin).
- If you sign in with SAML, a `Generic SAML` provider added before you enable Auth V2. See
  [Add Providers That Are Not Migrated](#add-providers-that-are-not-migrated).

## Enable Auth V2

<Tabs>
  <Tab title="Replicated">
    1. Open the Replicated Admin Console for your installation and go to the application configuration page.
    2. In the `Experimental` section, turn on `Enable OAuth V2 Login`.
    3. Save and deploy the updated configuration.
  </Tab>

  <Tab title="Kubernetes (Helm)">
    In your `values.yaml` for the `openhands` chart, set these environment variables:

    ```yaml
    env:
      ENABLE_OAUTH_V2_LOGIN: "true"
      OH_WEB_CLIENT_FEATURE_FLAGS_ENABLE_OAUTH_V2_LOGIN: "true"
    ```

    The Super Admin dashboard needs two more variables. Add them if they are not already set:

    ```yaml
    env:
      ENABLE_SUPER_ADMIN: "true"
      OH_WEB_CLIENT_FEATURE_FLAGS_ENABLE_SUPER_ADMIN: "true"
    ```

    Then redeploy the `openhands` chart.
  </Tab>

  <Tab title="Docker Compose">
    The Docker Compose install has Auth V2 turned on and uses the integrated password login, so there is nothing to
    migrate. To add more providers, see [Configure Auth Providers](/enterprise/auth-v2/configure-providers).
  </Tab>
</Tabs>

After you enable Auth V2:

- The login screen shows a button for each enabled login provider, instead of a fixed button for each Git provider.
- `Settings > Integrations` lists the Git providers that are enabled on the `Auth Providers` page.

## Review the Migrated Providers

Open the Super Admin dashboard and choose `Auth Providers`. The upgrade creates these providers from your existing
configuration, and they are enabled:

| Provider | Created when | Use |
| --- | --- | --- |
| `GitHub`, `GitLab`, `Bitbucket`, `Bitbucket Data Center`, `Azure DevOps` | The provider's OAuth app is configured on your installation. | Integration only. Users connect it from `Settings > Integrations`. |
| `Log in with GitHub`, `Log in with GitLab`, `Log in with Bitbucket` | The provider was available as a login option in V1. | Sign in, through your existing Keycloak client. |
| `Login with Password` (type `Integrated Password`) | Integrated password login was enabled. | Sign in with an email and password. |

Leave `Keycloak-federated git provider` as it is on the `Log in with` providers.

## Add Providers That Are Not Migrated

The Enterprise SSO (SAML) login from V1 isn't migrated. If you use it, add your identity provider with the
`Generic SAML` preset before you enable Auth V2. See the SAML tab in
[Configure Auth Providers](/enterprise/auth-v2/configure-providers#provider-details).

You can also add providers that were not available in V1, such as Okta or Google.

## Check Sign-In

1. Open OpenHands in a private browser window.
2. Sign in with each login provider you expect to see.
3. Confirm that you reach OpenHands and that `Settings > Integrations` lists your Git providers.

Users who already have an account are linked to it on their first sign-in through a provider, when that provider's
`Link existing accounts by email` setting is on. It is on for new providers by default.

## Turn Auth V2 Off

To return to V1 sign-in, turn off the setting that you turned on in [Enable Auth V2](#enable-auth-v2).

<Tabs>
  <Tab title="Replicated">
    Turn off `Enable OAuth V2 Login` in the `Experimental` section, then save and deploy the configuration.
  </Tab>

  <Tab title="Kubernetes (Helm)">
    Set `ENABLE_OAUTH_V2_LOGIN` and `OH_WEB_CLIENT_FEATURE_FLAGS_ENABLE_OAUTH_V2_LOGIN` to `"false"`, or remove them,
    then redeploy the `openhands` chart.
  </Tab>
</Tabs>

A later release will remove V1 sign-in, and you will no longer be able to turn Auth V2 off.
