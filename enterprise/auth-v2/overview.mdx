Auth V2 is a new way to manage how users sign in to OpenHands Enterprise and how they connect Git providers. A Super
Admin configures each **auth provider** on the `Auth Providers` page of the
[Super Admin dashboard](/enterprise/super-admin), instead of through deployment configuration and Keycloak.

## Auth V2 by Install Type

| Install type | Auth V2 status |
| --- | --- |
| [Docker Compose](/enterprise/docker-compose) | Enabled automatically. No migration is needed. |
| [Replicated VM](/enterprise/vm-install/generic-vm) and [Helm](/enterprise/k8s-install/index) | You may need to migrate from Auth V1, which requires Keycloak, to Auth V2, where Keycloak is optional. See [Migrate From V1 to V2](/enterprise/auth-v2/migrate-from-v1). |

## Benefits of Auth V2

- **Configure in the UI**: Add, edit, enable, disable, and delete providers from the Super Admin dashboard.
- **Control login and integrations separately**: For each Git provider, choose whether users can also sign in with it.
  Identity providers such as Okta are used only for sign-in.
- **More providers out of the box**: Start from a preset for Okta, Google, a generic OIDC or SAML provider, GitHub,
  GitLab, Bitbucket, Bitbucket Data Center, Azure DevOps, or Jira Data Center. You can also add an integrated password
  login.

## Provider Types

Every auth provider has one of three types:

| Type | Use it for |
| --- | --- |
| `OAuth` | Any OAuth 2.0 or OpenID Connect (OIDC) provider, including Git providers. |
| `SAML` | A SAML 2.0 identity provider. |
| `Integrated Password` | Email and password login handled by OpenHands, with no external provider. |

## Login and Integrations

An auth provider can be a **login provider**, a **built-in integration**, or both. Its type decides which.

| Provider | Login provider | Built-in integration |
| --- | --- | --- |
| Okta, Google, and generic OAuth or OIDC (provider `Enterprise SSO`) | Yes | No |
| SAML | Yes | No |
| Integrated Password | Yes | No |
| Jira Data Center | Yes | No. The [Jira Data Center integration](/enterprise/auth-v2/configure-providers#use-jira-data-center-sign-in-with-the-integration) reuses its sign-in. |
| GitHub, GitLab, Bitbucket, Bitbucket Data Center, Forgejo, and Azure DevOps | When `Use as OpenHands Authentication Provider` is on | Yes |

Every enabled Git provider is available to users as an integration. Its `Use as OpenHands Authentication Provider`
setting decides whether it is also a sign-in option:

- **Integration only**: Turn the setting off. Users connect the provider from `Settings > Integrations` after they sign
  in another way.
- **Sign-in and integration**: Turn the setting on. The provider appears as a button on the login screen. Signing in
  with it also connects it as an integration for that user.

To set up providers, see [Configure Auth Providers](/enterprise/auth-v2/configure-providers).

## Licensing

Adding or enabling a SAML provider or a direct OIDC provider (Okta, Google, or generic OAuth or OIDC) for login requires a
license that includes SSO. Git providers, Jira Data Center, and the integrated password login do not.
