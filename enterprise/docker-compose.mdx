The Docker Compose stack runs OpenHands Enterprise on a single machine. Use it to evaluate
OpenHands Enterprise with a small group of users. For production, we recommend
[Kubernetes](/enterprise/k8s-install/index).

## Prerequisites

- Git
- Docker and Docker Compose
- An API key from your LLM provider

## Install

<Steps>
  <Step title="Start the stack">
    ```bash
    git clone https://github.com/OpenHands/enterprise.git
    cd enterprise
    docker compose up --wait
    ```

    The command returns when every service is healthy. On the first start, the application pulls
    the agent sandbox image before it reports healthy, which can take several minutes. To follow
    its progress, run `docker compose logs -f app` in another terminal.
  </Step>
  <Step title="Complete onboarding">
    Open [http://localhost:3100](http://localhost:3100) and follow the onboarding flow to create
    your first user and configure your LLM provider.
  </Step>
</Steps>

After you sign in, OpenHands opens Agent Canvas at
[http://localhost:3100/canvas/](http://localhost:3100/canvas/).

## Configuration

Set these variables in your shell or in a `.env` file in the `enterprise` directory:

| Variable | Default | Description |
|----------|---------|-------------|
| `APP_PORT` | `3100` | The port that OpenHands is served on. |
| `WEB_HOST` | `localhost` | The hostname that users enter in their browser. |
| `WEB_URL` | `http://localhost:3100` | The full URL that users enter in their browser. |
| `AGENT_CANVAS_LOCK_TO_CLOUD` | `http://localhost:3100` | The URL that Agent Canvas connects to. Set it to the same value as `WEB_URL`. |
| `DB_USER`, `DB_PASS`, `DB_NAME` | `openhands` | The PostgreSQL credentials and database name. |

To reach OpenHands from another machine, set `WEB_HOST`, `WEB_URL`, and
`AGENT_CANVAS_LOCK_TO_CLOUD` to match the address in the browser exactly. For example:

```bash .env
WEB_HOST=openhands.example.com
WEB_URL=https://openhands.example.com
AGENT_CANVAS_LOCK_TO_CLOUD=https://openhands.example.com
```

Set the database credentials before the first start. PostgreSQL keeps the credentials it was
created with, so changing them later requires a [reset](#reset).

## Upgrade

Pull the latest changes, then restart the stack:

```bash
git pull
docker compose down
docker compose up --wait
```

The application migrates its database on startup.

## Stop and reset

Stop the stack with:

```bash
docker compose down
```

Your data is stored in Docker volumes and is kept when you stop the stack.

### Reset

To delete all data and start over, stop any running sandbox containers, then remove the volumes:

```bash
docker compose down -v
```
