The Docker Compose stack runs OpenHands Enterprise on a single machine. Use it to evaluate
OpenHands Enterprise with a small group of users. For production, we recommend
[Kubernetes](/enterprise/k8s-install/index).

## Prerequisites

- Git
- Docker and Docker Compose
- Model credentials for your chosen [model or gateway setup](/enterprise/integrations/models-and-gateways)

## Install

<Steps>
  <Step title="Start the stack">
    ```bash
    git clone https://github.com/OpenHands/enterprise.git
    cd enterprise
    ./scripts/setup.sh
    ```

    The script returns when every service is healthy, then prints the URL to open. On the first
    start, the application pulls images, which can take several minutes.
  </Step>
  <Step title="Complete onboarding">
    Open the URL the script printed and follow the onboarding flow to create your first user and
    configure your LLM provider.
  </Step>
</Steps>

On a fresh stack, follow the first Super Admin's
[setup guide](/enterprise/super-admin#setup-guide) to add an LLM, connect Git, and invite users.
This Enterprise guide is separate from the
[local Agent Canvas first-time wizard](/openhands/usage/agent-canvas/first-time-setup).

## Connect Amazon Bedrock

For AWS credential forwarding, model profile setup, and a full agent verification
task, follow the Docker Compose tab in the
[AWS Bedrock integration guide](/enterprise/integrations/aws-bedrock-llm-gateway).

Use the same Compose options for lifecycle commands. For a stack that uses only the base
file and the Bedrock override, pass `-f docker-compose.yml -f compose.bedrock.yaml` to
both `docker compose` and `./scripts/setup.sh`. Retain any additional Compose files, project
name, and environment-file options your installation uses.

## Share with your team

By default, the stack is only reachable from the machine it runs on. To share it with others,
serve it over HTTPS with [ngrok](/enterprise/docker-compose/ngrok) or run it on a
[VM with your own domain](/enterprise/docker-compose/https).

## Upgrade

Pull the latest changes, then restart the stack. If you use an override, keep
the complete Compose file list as described above. After pulling, compare the
updated default `OH_AGENT_SERVER_ENV` entries with your override before
recreating services, so the override retains any newly required entries:

```bash
git pull
docker compose down
./scripts/setup.sh
```

The application migrates its database on startup.

## Stop and reset

Stop the stack with:

```bash
docker compose down
```

Your data is stored in Docker volumes and is kept when you stop the stack.

### Reset

To delete all data and start over, stop any running sandbox containers, then remove the volumes:

```bash
docker compose down -v
```
