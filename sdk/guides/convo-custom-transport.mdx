---
title: Custom Event Transports
description: Supply a per-conversation event client while retaining remote conversation lifecycle management.
---

`RemoteConversation` receives live events through a WebSocket client. Use
`websocket_client_factory` to provide another implementation, such as a client
that connects over a Unix-domain socket. Each conversation receives its own
client, so conversations in one process can use different transports.

## Client Contract

The SDK exports two structural protocols from `openhands.sdk`:

- `WebSocketClient` exposes the writable `callback: ConversationCallbackType`
  attribute and describes `start()`, `stop()`, and
  `wait_until_ready(timeout: float | None = None) -> bool`.
- `WebSocketClientFactory` constructs a `WebSocketClient` from the keyword
  arguments `host`, `conversation_id`, `callback`, `api_key`, and `on_reconnect`.

Your client can implement these methods without inheriting the SDK's default
client. The factory returns a new, unstarted client. The SDK starts it, waits for
subscription readiness, reconciles stored events, and stops it when the
conversation closes or connection initialization fails.

The transport must:

1. Authenticate using the supplied session API key when authentication is
   required. For the Agent Server events socket, send
   `{"type": "auth", "session_api_key": "..."}` as the first message after
   connecting. Keep credentials out of URLs and logs.
2. Store the supplied callback in the writable `callback` attribute and forward
   decoded SDK `Event` objects to it.
3. Report readiness after the server acknowledges the subscription with its
   initial state event.
4. After reconnecting and restoring the subscription, invoke `on_reconnect`
   before forwarding events from that connection. This reconciles events that
   were persisted while the client was disconnected.
5. Release its connections and background workers in `stop()`.

## Supply a Factory

The following example assumes that your package provides an `EventClient`
implementing the contract above. Replace that import with your implementation.

```python icon="python"
from collections.abc import Callable

from my_transport import EventClient

from openhands.sdk import Conversation, WebSocketClient, WebSocketClientFactory
from openhands.sdk.conversation import ConversationCallbackType


def make_event_client(
    *,
    host: str,
    conversation_id: str,
    callback: ConversationCallbackType,
    api_key: str | None,
    on_reconnect: Callable[[], object] | None,
) -> WebSocketClient:
    return EventClient(
        host=host,
        conversation_id=conversation_id,
        callback=callback,
        api_key=api_key,
        on_reconnect=on_reconnect,
    )


factory: WebSocketClientFactory = make_event_client
conversation = Conversation(
    agent=agent,
    workspace=remote_workspace,
    websocket_client_factory=factory,
)
try:
    conversation.send_message("Inspect the project.")
    conversation.run()
finally:
    conversation.close()
```

`remote_workspace` must be a `RemoteWorkspace`. Supplying a factory for a local
workspace raises `ValueError`.

The factory configures the event transport. REST requests continue to use
`remote_workspace.client`; a Unix-domain-socket deployment also needs an HTTP
client configured for that socket.

## Create, Attach, and Fork

Direct construction, `RemoteConversation.create()`, and
`RemoteConversation.attach()` accept the same optional factory:

```python icon="python"
from openhands.sdk import RemoteConversation

created = RemoteConversation.create(
    remote_workspace,
    start_request,
    websocket_client_factory=factory,
)
attached = RemoteConversation.attach(
    remote_workspace,
    conversation_id,
    websocket_client_factory=factory,
)

attached.close()
created.close()
```

The factory is client-side configuration. It is not sent in the creation request
or persisted by the server, so provide it again when attaching from a new client.

`conversation.fork()` retains the parent's factory and creates an independent
event client for the fork. Closing the fork leaves the parent's client running.

When the factory is omitted, the SDK selects its default WebSocket client when
each connection is initialized.
