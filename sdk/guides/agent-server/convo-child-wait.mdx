title: Wait for Child Conversations
description: Await existing child conversations on the agent server without polling.

<Note>
This guide accompanies the backend foundation for [SDK issue #6129](https://github.com/OpenHands/software-agent-sdk/issues/6129). The endpoint must be present in your server build. It is not available in the v1.58.1 release. Mailbox result delivery and an agent tool remain separate integration work.
</Note>

Use one server request to wait for existing direct child conversations. The server uses execution lifecycle notifications, so the parent and children can run without an attached browser or WebSocket.

## Wait Request

Call `POST /api/conversations/{parent_id}/children/wait` with the server's session API key. The children must belong directly to that parent on the same agent-server instance.

```json
{
  "conversation_ids": ["a-child-conversation-uuid"],
  "timeout_seconds": 60,
  "delete_on_finish": false,
  "on_timeout": "retain"
}
```

| Field | Meaning |
| --- | --- |
| `conversation_ids` | Between 1 and 64 unique, existing direct child UUIDs. |
| `timeout_seconds` | Finite wait duration from 0 to 300 seconds; default 60. |
| `delete_on_finish` | Delete settled children after waiting; default false. |
| `on_timeout` | `retain` (default), `stop`, or `delete` for children still pending at the deadline. |

The deadline starts after validation and runtime loading. Stop/delete cleanup follows the existing conversation lifecycle and can extend the total request duration. Synchronous workers retain their existing cooperative interruption limitations.

## Response

```json
{
  "children": [{
    "conversation_id": "a-child-conversation-uuid",
    "execution_status": "finished",
    "settled": true,
    "deleted": false
  }],
  "timed_out": false,
  "interrupted": false
}
```

Each entry describes the child's state **before cleanup**. `settled` means its run completed, failed, became stuck, was explicitly paused, or its service began closing. A provisional `finished` state inside a running step does not settle the wait before the run and stop hooks finish.

On timeout, the server returns HTTP 200 with `timed_out: true` and the pending children's current observed execution states. Completed children remain marked `settled: true`. The timeout is a normal result.

A parent pause, interrupt, or close returns `interrupted: true` without applying timeout cleanup. Disconnecting or cancelling a pending wait releases the waiters and leaves child execution running. Any destructive cleanup that has already started is drained before the request exits.

Cleanup skips a child that has started another run. Check `deleted` to see whether this request removed it. Keep the default retention policy if you still need to read the child's history or final response. This operation returns lifecycle states only; finish-result delivery belongs to [the mailbox feature, #6127](https://github.com/OpenHands/software-agent-sdk/issues/6127).

## TypeScript Client

A client build containing `ConversationClient.waitForChildren` can call the same endpoint:

```typescript
const result = await client.waitForChildren(parentId, {
  conversation_ids: childIds,
  timeout_seconds: 120,
});
```

An optional third argument accepts an `AbortSignal` and a transport timeout. By default, the transport timeout is 30 seconds longer than the requested wait. Increase it if runtime loading or cleanup may take longer.

Unknown parents or non-child IDs return 404. Invalid IDs, duplicate IDs, empty lists and out-of-range timeouts return 422. Authentication follows the existing session-key policy.
